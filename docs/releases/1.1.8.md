# CWS 1.1.8 (build 14)

YSK Limited · phone `hk.ysk.cws` · CWS Proxy `hk.ysk.cws.proxy`

Product: https://ysk.hk/products/ysk-cold-wallet-simulator

This note covers what landed after 1.1.7 (build 13): Sunday true-device protocol parity for Trezor firmware 2.13.1 Solana v1 / sysvar checks and Ledger Cardano 8.0.11 host-address length. It does not attach binaries. Signing identities and keystores are not in git. Seeds are not absolutely safe, and they are not hardware-wallet safe.

## English

CWS is a phone simulator for developers and wallet teams testing interoperability with selected Ledger, Trezor, and OneKey Bluetooth models. It is not a secure element. Ledger, Trezor, and OneKey do not endorse it. Do not use it to hold real digital assets.

**Seeds are not absolutely safe.** The public statement is [docs/security.md](https://github.com/yanshekki/ysk-cold-wallet-simulator/blob/main/docs/security.md). The 1.1.7 overlay and 1.1.6 TON baseline still apply.

### What 1.1.8 changes

- Trezor Features report firmware **2.13.1** (`data.trezor.io/firmware/t3w1/releases.json`, revision `4289e23b317e98ab6a5e8237723e0cd57f44934c`).
- Solana SignTx parses SIMD-0385 v1 messages (header `0x81`, config mask, instruction headers then payloads) and signs those bytes. Version 2 and truncated bodies fail as Trezor `DataError` / `Invalid transaction`.
- Solana SignTx rejects Stake/System/Token instructions whose named sysvar slot holds a different account or an address-lookup-table reference, matching trezor-firmware `SYSVAR_ACCOUNTS`.
- Ledger Cardano third-party outputs and CIP-36 payment addresses must match 8.0.11 Shelley length rules (and Byron ≤ 108 bytes). Wrong-length bodies fail as `0x6a80` (`SW_TX_BODY`). The canonical tx-body hash of a valid payment is unchanged.
- CWS Proxy is unchanged and remains 1.1.6 (build 12). The lab Solana SignTx fixture is a valid legacy transfer so it still signs after the Trezor parser.

### 1.1.8 改變了甚麼

- Trezor Features 回報韌體 **2.13.1**（`data.trezor.io/firmware/t3w1/releases.json`，revision `4289e23b317e98ab6a5e8237723e0cd57f44934c`）。
- Solana SignTx 解析 SIMD-0385 v1 訊息（標頭 `0x81`、config mask、先指令標頭再 payload），並簽署該些位元組。版本 2 與截斷的主體會以 Trezor `DataError`／`Invalid transaction` 失敗。
- Solana SignTx 會拒絕 Stake／System／Token 指令中，具名 sysvar 欄位放了其他帳戶或地址查找表引用的交易，對齊 trezor-firmware `SYSVAR_ACCOUNTS`。
- Ledger Cardano 第三方輸出與 CIP-36 付款地址須符合 8.0.11 的 Shelley 長度規則（Byron ≤ 108 位元組）。錯誤長度的主體以 `0x6a80`（`SW_TX_BODY`）失敗。有效付款的規範交易主體雜湊不變。
- CWS Proxy 沒有改動，仍為 1.1.6（組建編號 12）。實驗室的 Solana SignTx 樣本改為有效的舊式轉帳，以便在 Trezor 解析器之後仍能簽署。
