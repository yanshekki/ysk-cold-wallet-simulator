# CWS 1.1.5 (build 11)

YSK Limited · phone `hk.ysk.cws` · CWS Proxy `hk.ysk.cws.proxy`

Product: https://ysk.hk/products/ysk-cold-wallet-simulator

This note covers what landed after 1.1.4 (build 10): Cardano CIP-36 auxiliary registration, pool-registration certificates, and voting procedures now hash the canonical body Ledger firmware hashes. It does not attach binaries. Signing identities and keystores are not in git. Seeds are not absolutely safe, and they are not hardware-wallet safe.

## English

CWS is a phone simulator for developers and wallet teams testing interoperability with selected Ledger, Trezor, and OneKey Bluetooth models. It is not a secure element. Ledger, Trezor, and OneKey do not endorse it. Do not use it to hold real digital assets.

**Seeds are not absolutely safe.** The public statement is [docs/security.md](https://github.com/yanshekki/ysk-cold-wallet-simulator/blob/main/docs/security.md). The 1.1.4 baseline still applies.

### What 1.1.5 changes

- Cardano `SIGN_TX` CIP-36 auxiliary registration is FIXED. v8 P1 `13` and v7 P2 `34` return `auxHash(32) ‖ signature(64)`. The signed digest is blake2b-256 of `Map(1){61284: payload}` from LedgerHQ/app-cardano `src/cvote/aux_data_hash_builder.c`. Hashing the payload map alone, or the concatenated APDU, does not verify. The auxiliary hash is transaction-body field 7. Incomplete CIP-36 still returns `6A80` / `6980` / `6B50`. Tests: `cardanoAux.test.ts`, `cardanoTxHash.test.ts`, `cardanoTxV7.test.ts`.
- Pool-registration certificates (type 3) encode Conway `Array(10)` as in `src/transaction/tx_hash_builder.c`. Voting procedures are body field 19. Witnesses sign blake2b-256 of that canonical body. A wrong hash fails. App versions before 2.2 stay `6A80`.
- TON cell-hash, Solana INS `21` / `22`, Bitcoin policy HMAC, and Ethereum clear-sign stay KEEP. Phantom unlock, Rabby scan, Avalanche Core X/P listing, and OKX asset display stay host-only KEEP. CWS Proxy hold-forwards an unarmed empty `9000` for a CIP-36 INIT that still has delegations. Proxy runtime adapters did not change.

### 1.1.5 改變了甚麼

- Cardano `SIGN_TX` 的 CIP-36 輔助登記已 FIXED。v8 的 P1 `13` 與 v7 的 P2 `34` 回傳 `auxHash(32) ‖ signature(64)`。簽署摘要是 LedgerHQ/app-cardano `src/cvote/aux_data_hash_builder.c` 所述、對 `Map(1){61284: payload}` 做 blake2b-256。只雜湊 payload map，或雜湊串接的 APDU，均無法驗證。該輔助雜湊是交易主體欄位 7。未完成的 CIP-36 仍回傳 `6A80`／`6980`／`6B50`。測試：`cardanoAux.test.ts`、`cardanoTxHash.test.ts`、`cardanoTxV7.test.ts`。
- 權益池登記憑證（類型 3）按 `src/transaction/tx_hash_builder.c` 編成 Conway `Array(10)`。投票程序是主體欄位 19。見證對該規範主體的 blake2b-256 簽署。錯誤雜湊會失敗。2.2 之前的應用版本仍是 `6A80`。
- TON cell-hash、Solana INS `21`／`22`、Bitcoin 策略 HMAC，以及以太坊 clear-sign 仍是 KEEP。Phantom 解鎖、Rabby 掃描、Avalanche Core 的 X／P 列出，以及 OKX 資產顯示，仍是只限主機的 KEEP。CWS Proxy 會暫存尚未 armed 的空 `9000`，包括仍有授權項的 CIP-36 INIT。代理程式執行期轉接器沒有改動。
