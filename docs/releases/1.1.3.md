# CWS 1.1.3 (build 9)

YSK Limited · phone `hk.ysk.cws` · CWS Proxy `hk.ysk.cws.proxy`

This note covers what landed after 1.1.2 (build 8): the proxy Bluetooth lock (#77) and vendor BLE service UUIDs with a per-phone OneKey name (#78). It does not attach binaries. Signing identities and keystores are not in git. Seeds are not hardware-wallet safe.

## English

CWS is a phone simulator for developers and wallet teams testing interoperability with selected Ledger, Trezor, and OneKey Bluetooth models. It is not a secure element. Ledger, Trezor, and OneKey do not endorse it. Do not use it to hold real digital assets.

**Seeds are not hardware-wallet safe.** The public statement is [docs/security.md](https://github.com/yanshekki/ysk-cold-wallet-simulator/blob/main/docs/security.md). The 1.1.2 baseline still applies.

### What 1.1.3 changes

- CWS Proxy lists nearby phones: advertised name, the Bluetooth id, and RSSI when the operating system reports it. Choosing one writes a local lock with that id and name, not a seed. Reconnects, including after a restart, stay on that peripheral until Unlock / Change device. macOS stores the file at `~/Library/Application Support/CWS Proxy/ble-lock.json`. Linux uses `~/.config/cws-proxy/ble-lock.json`, or `$XDG_CONFIG_HOME/cws-proxy/ble-lock.json` when that variable is set. With no lock file, `cws-proxy --no-ui` still connects to the highest-ranked advertiser. The proxy still only forwards bytes.
- Phone BLE service UUIDs come from the vendor tables. Ledger models advertise distinct services (Nano X `0004`, Flex `3004`, Stax `6004`, Nano Gen5 `8004`). Trezor Safe 7 keeps the THP service `8c000001-a59b-4d58-a9ad-073df69fa1b1`. OneKey models share `00000001-0000-1000-8000-00805f9b34fb` and are told apart by the GAP name. Each phone stores a stable 4-digit token in that name: `K` / `P` / `T` plus digits, `1S` plus hex, or `Pro` / `Pro 2` / `Neo` plus hex. Two OneKey phones no longer reuse one GAP serial. A scan that omitted the 128-bit service UUID no longer opens every phone on that shared OneKey service.

### 1.1.3 改變了甚麼

- CWS Proxy 列出附近的電話：廣播名稱、藍牙識別碼，以及作業系統有提供時的 RSSI。選擇一部電話會把該識別碼與名稱寫入本機鎖定檔，不含種子。重新連線，包括重新啟動之後，都會留在該周邊，直到按下解除鎖定。macOS 的檔案是 `~/Library/Application Support/CWS Proxy/ble-lock.json`。Linux 用 `~/.config/cws-proxy/ble-lock.json`；若已設定 `$XDG_CONFIG_HOME`，則放在其下的 `cws-proxy/ble-lock.json`。沒有鎖定檔時，`cws-proxy --no-ui` 仍會連接排名最高的廣播。代理仍然只轉送位元組。
- 手機的 BLE 服務 UUID 來自供應商表。Ledger 各型號廣播不同的服務（Nano X `0004`、Flex `3004`、Stax `6004`、Nano Gen5 `8004`）。Trezor Safe 7 仍用 THP 服務 `8c000001-a59b-4d58-a9ad-073df69fa1b1`。OneKey 各型號共用 `00000001-0000-1000-8000-00805f9b34fb`，並以 GAP 名稱區分。每部電話在該名稱放入一個穩定的四位代號：`K`／`P`／`T` 加數字、`1S` 加十六進制，或 `Pro`／`Pro 2`／`Neo` 加十六進制。兩部 OneKey 電話不再共用同一個 GAP 序號。略去 128-bit 服務 UUID 的掃描，不會再把每部電話都當成該共用 OneKey 服務開啟。
